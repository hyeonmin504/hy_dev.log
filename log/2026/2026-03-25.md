# 2026-03-25

**요약**: 경기장 배정에 "그룹" 엔티티를 넣고, 선수·팀·지도자의 외부 기관 코드를 종목별 1:N으로 담는 외부 식별자 테이블을 설계했다. 둘 다 당장은 작은 변경이었는데 두 달 뒤 큰 기능의 바닥이 됐다.

입사 한 달쯤. 경기장 배정 API가 매치 순서를 정할 때 "같은 조끼리 묶어서"라는 조건이 필요해졌다. 처음엔 경기장에 순서 있는 하위 목록을 두려 했는데, 써 보니 그룹 자체엔 순서가 필요 없고 매치와의 연관만 있으면 됐다. 그래서 경기장 안의 그룹 엔티티를 순서 없는 묶음으로 두고, 순서는 매치 쪽 정렬 조건에 그룹을 끼워 넣는 걸로 정리했다.

같은 주에 선수·팀·지도자가 외부 기관 코드를 가질 수 있어야 한다는 요구가 왔다. 엔티티마다 코드 컬럼 하나를 두면 끝날 것 같지만, 종목마다 다른 기관이 다른 코드를 주고 연도별로도 갈릴 수 있었다. 그래서 별도 테이블 하나로 뺐다. 어떤 엔티티의 것인지(entity_type), 어느 기관인지(data_source), 종목·연도, 코드, 그리고 기관마다 모양이 다른 부가 정보는 JSON 한 칸. 우리 엔티티 1건에 외부 식별자 N건이 붙는 구조다.

이때는 "나중에 쓸지도 모르니 넓게"였는데, 6월에 외부 연맹 연동이 이 테이블 위에 그대로 올라갔다. 그때 바꾼 건 없고 구체 타입 3개를 얹었을 뿐이다. 반대로 경기장 그룹은 6월에 "조 분할은 요청이 단독 결정한다"로 역할이 한 번 바뀐다.
