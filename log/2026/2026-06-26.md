# 2026-06-26

**요약**: 지도자 회원탈퇴를 hard delete 대신 "최소 신원 보존 + 민감정보 null + 옛 아이디를 점유하는 tombstone 행"으로 바꾸고, 재가입은 활성 중복차단(DI)과 탈퇴 복원 매칭(이름·생년·성별)을 다른 키로 갈랐다. PR 7개, 한 번 뒤집힌 결정 하나.

## 배경과 제약
지도자 계정은 대회 등록·팀 운영·활동 로그의 행위 주체라 물리 삭제하면 FK와 이력이 끊긴다. 같은 아이디로 타인이 재가입하면 과거 행위자와 혼동된다. 개인정보상 인증 정보는 보관하면 안 되지만, 아이디 재사용 차단과 본인 재가입 복원을 위해 최소 신원은 필요했다. 선수 쪽은 이미 같은 패턴을 쓰고 있었다.

## 선택
| 선택지 | 결과 | 이유 |
|---|---|---|
| hard delete | 탈락 | 이력 단절, 아이디 재사용 차단 불가 |
| 삭제 플래그만 | 탈락 | 민감정보 잔존, 아이디가 원본 행에 묶임 |
| 이름·생년·성별만 보존 + 나머지 null + 옛 아이디 점유 tombstone 행 | **채택** | 선수 패턴과 미러 |

저장 순서는 원본 익명화 → flush → tombstone 저장. 로그인 조회는 "삭제 안 된 것만"으로 바꿔야 한다. 안 그러면 비밀번호가 null인 tombstone 행이 로그인 시도에 걸린다.

재가입 분기 순서는 옛 아이디 재사용 차단 → DI가 같은 활성 계정 차단 → 탈퇴 신원 매칭(1건이면 복원, 2건 이상이면 임의 선택 대신 전용 에러 + 고객센터) → 신규. 활성 중복은 DI, 복원은 신원 3요소로 **일부러 다른 키**를 쓴다. 활성 지도자 중 이름·생년·성별이 같은 동명이인이 여럿 있어서 신원으로 막으면 오차단이 나고, 탈퇴 행은 DI를 비우니 복원엔 DI를 쓸 수 없다. CI는 범용·민감 식별자라 서비스 내 중복 확인엔 DI가 맞다.

## 막혔던 것 — 뒤집힌 결정
처음엔 "재가입하면 당해연도 팀 등록도 자동 복원"으로 갔다가 폐기했다. 복원은 계정만 살리고 팀 소속은 건드리지 않는다. 팀 복구는 팀 생성·연동 시점에 "같은 이름 + 같은 대표(소유주)면 자동, 그 외는 어드민 승인"이라는 규칙 하나로 통일했다. 회원탈퇴와 팀 떠나기 양쪽에 같은 규칙이 걸린다.

이 과정에서 갭 두 개가 드러났다. 혼자 남은 대표가 떠나면 코치 0명 유령 팀이 남는 것(팀 등록도 비활성으로), 소유주가 같은 이름으로 팀을 다시 만들면 승인 없이 재활성화해야 하는데 이름 중복 검사가 비활성 팀도 막고 있던 것(소유주 분기를 그 검사보다 먼저).

## 결과와 대가
- 탈퇴·재가입·팀 비활성이 대회·경기 기록과 양방향으로 격리되는지 따로 검증했다. 대회 기록은 전부 등록 시점 스냅샷이라 마스터 변경이 과거 기록을 흔들지 않고, 경기·점수·상장은 마스터 엔티티에 쓰지 않는다.
- 대가: 동명이인이 탈퇴 계정을 복원해 가로채는 위험(revive-theft)이 남는다. 막으려면 탈퇴 시 CI를 보존해야 하는데 프라이버시 때문에 안 했다. 신고가 쌓이면 재검토.
- 구 스킴 탈퇴 데이터(아이디 유지 + 이름 null)는 이름이 없어 복원 불가. 신규 가입으로만 처리된다. 데이터 복구는 불가능하고 무해하다.
