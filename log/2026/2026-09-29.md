# 2026-09-29

**요약**: 매일 사람이 10분씩 손으로 하던 "외부 기관 데이터 수신 → 사내 DB 동기화 → 슬랙 보고"를 Windows 작업 스케줄러와 화면 자동 조작으로 무인화했다. 평일 매시 10회 실행, 스케줄러 3회 검증 통과. 대가는 매 회차 3분 30초의 데이터 공백과 매시간 부하.

## 배경과 제약
외부 기관이 배포한 수신 프로그램은 PowerBuilder로 만들어져 소스도 명령줄 옵션도 없다. 로그인하면 수신 화면이 열리고 '수신'을 누르면 기존 데이터를 지우고 다시 받는다. 약 3분 30초, 팀 1.4k·지도자 3.3k·선수 15k건. 수신 서버와 두 DB 모두 사내망에서만 열리고, 실행 PC는 밖으로 들고 나가는 노트북이다. 동기화 서비스는 비공개 레포의 Spring Boot 앱이고, 슬랙 보고는 기존처럼 본인 이름으로 리마인더 스레드에 달아야 했다.

## 선택
- 수신 프로그램은 수정 불가라 사람 조작을 그대로 재현하는 화면 자동화로. 컨트롤은 화면상 고유 ID로 찾고, 창 문구는 Win32로 직접 읽는다.
- 일정은 클라우드 루틴이 불가(사내망·화면 필요)라 Windows 작업 스케줄러. 로그온 상태에서만 돌고, 놓친 회차는 다음 로그인 때 한 번만 몰아서. BIOS 예약 부팅과 자동 로그인은 보안 때문에 뺐다.
- 레포 인증은 배포 키가 관리자 권한을 요구해서 GitHub CLI 로그인 유지로.
- 슬랙은 Webhook이 스레드 답글 불가, 봇은 본인 이름이 아니라서 둘 다 탈락. User 토큰으로 직접 보내고 실패 시에만 Claude 연결로 대체. 봇 → Claude 연결 → User 토큰으로 두 번 바꿨다.
- 빈도는 1회 → 2회 → 평일 09~18시 매시(10회)로 늘렸다.

## 흐름
```pseudo
회차 시작(스케줄러, 이전 회차 실행 중이면 건너뜀):
  사내망 확인 = 두 DB에 실제 접속 시도 (10초 간격, 최대 7회)   # 와이파이 이름은 신뢰하지 않는다
  if 실패: 로그만 남기고 종료                                   # 수신 프로그램을 안 띄움 = 데이터 삭제 없음
  수신:
    기존 프로세스 종료 → 재실행 → 로그인
    '수신' 클릭 → 확인창 문구 == "다시 수신" 일 때만 확인       # 문구 검증 없이는 누르지 않는다
    5초마다 완료창 폴링, 문구 == "수신했습니다" 만 성공. 프로세스 소멸 = 즉시 실패
  동기화:
    레포 pull → 변경 있을 때만 빌드 (실패 시 기존 바이너리로 진행)
    운영 설정으로 기동(최대 3분 대기) → API 호출 → "완료" 확인 → 종료
  보고: 채널 최신 글의 스레드에 결과. 성공이면 원글에 체크 반응, 실패면 단계·오류·로그 위치
  공통: 수신·동기화 각각 실패 시 5분 후 1회 재시도, 실행 중 절전 방지, 회차 로그 60일
```
비밀 정보는 Windows 암호화(DPAPI)로 이 PC·이 계정에서만 풀리게 저장했다.

## 막혔던 것
- 테스트 중 노트북이 절전에 들어가 수신이 끊겼다. 실행 중 절전 방지를 넣었다. 무인 장기 작업엔 기본으로 넣을 것.
- 직접 실행하면 읽히던 확인창 문구가 스케줄러로 돌리면 비어 보였다. 읽기 방식을 Win32로 바꿔 해결. 이때 "문구를 확인한 뒤에만 누르기" 가드 덕에 삭제 후 재수신이 잘못 실행되지 않고 멈췄다. 테스트는 처음부터 실제 실행 경로(스케줄러)로 해야 한다.
- PowerShell 5.1에서 한글 인코딩, TLS 설정, 외부 명령 오류 처리 세 군데가 걸렸다.
- 슬랙 앱을 짧은 시간에 여러 번 만들다 생성 제한에 걸렸다. 알림을 누구 이름으로 몇 번 보낼지는 구현 전에 확정했어야 했다.
