# 2026-07-02

**요약**: 선수 불참 때 상장 화면에 빈 행이 남는 버그를 고치다가 "숨기기만 하는" 접근(A)이 재순위를 막는다는 걸 실측으로 확인하고, 매치 확정마다 체급 상장을 통째로 재구성하는 단일 경로(B)로 갈아탔다. 증분 등록 경로는 죽은 코드가 돼 제거.

## 배경과 제약
상장 등록 경로가 두 벌이었다. 매치 확정 시 승자·패자를 순위에 더하는 증분 등록과, 체급 상장을 매치 결과로 다시 그리는 재구성. 불참·재참여가 생기면 빈 상장 행을 숨겨야 하는데 어느 쪽이 책임지는지가 불분명했다.

## 막혔던 것 — A안의 실패
처음엔 외과적으로 갔다. 불참 선수의 상장 행만 숨기는 증분 hide. 구현하고 돌려 보니 틀렸다. 4명 중 3명이 불참한 체급에서 실제 우승자가 rank 3에 방치되고 rank 1은 숨김 상태였다. 매치는 그 선수가 준결승·결승을 이긴 걸로 돼 있는데 상장은 안 따라왔다.

원인은 순서였다. 재순위 파이프라인이 그 선수를 rank 1로 올리려는데, rank 1 슬롯이 이미 "숨김"이라 "숨김이 아닌 슬롯에만 배정" 필터에 막혔다. 숨김이 할당보다 먼저 와서 정당한 승격을 차단한 것이다. 토너먼트는 위치 기반이라 sticky해도 될 줄 알았는데, 불참 캐스케이드는 토너먼트에도 재순위를 일으킨다. 리그가 승수 기반이라 완전 리셋으로 처리하던 이유와 같은 이유였다.

## 선택
B. 매치 확정마다 그 체급의 상장을 **[원하는 점유자 수집 → 기존 행에 재배정(재사용) → 불참·공석 hide]** 순으로 재구성한다. hide가 할당 뒤에 오니 승격을 막을 수 없다.

```pseudo
상장 재구성(대회, 체급):
  if 순수 리그(리그 라운드 있고 토너먼트 결승 없음): return   # 리그 처리기가 자체 재계산
  원하는점유자 = 수집(확정된 매치들)          # 승자·패자 판정은 기존 증분 로직을 그대로 미러
  for rank in 1..N:
      행 = 기존 행 재사용 or 생성
      if 점유자 있음 and 참가: 행.배정(점유자)
      elif 점유자 있음 and 불참: 행.불참숨김(점유자)   # 이름은 비우고 식별자는 남긴다 — 복원 식별용
      else: 행.숨김                                    # ← hide는 항상 마지막. 할당을 못 막는다
```

- 트리거는 코어의 "매치 확정" 한 곳만. "이미 진 선수를 사후 불참"처럼 매치 상태가 안 바뀌는 드문 경우는 미커버로 두고 수동 대응(사용자 결정, 트리거를 한 곳으로).
- 구조적 숨김과 불참 숨김은 참가자 참조의 유무로 암묵 구분. 마이그레이션 없음.
- 혼합형(리그 + 결승)은 처음엔 "리그 있으면 skip"이라 빠졌다. 조건을 "순수 리그만 skip"으로 좁혀 커버.

## 결과와 대가
- 증분 등록과 하위 메서드 제거. 재구성이 매번 덮어써서 증분은 실효가 없는 죽은 코드였다. 3인 리그 동률 재경기 자동 생성 잔재도 같이 제거(3월 핫픽스로 비활성화됐던 것, `git log -S`로 확인).
- 골든 테스트 매치 타입 8종(토너먼트·패자부활·3/4위전·3인 노크아웃·혼합형·리그·불참·생성).
- 대가: 새 메달 규칙이 생기면 확정 수집과 미확정 판정의 미러 두 곳을 같이 고쳐야 한다.
- 교훈: "숨기기"는 상태 변경이고, 상태 변경이 다른 할당의 입력이 되면 순서가 곧 정합성이다.
