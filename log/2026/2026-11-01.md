# 2026-11-01

**요약**: 대학 AI 캡스톤 수업 학생 5명에게 줄 과제 환경을 하루 만에 만들었다. 과제는 대회 공고 hwp를 AI로 읽어 관리 화면의 대회 생성 폼을 채우고, 체급표를 우리 체급 목록에 연결하는 것이다. 핵심 결정은 둘이다. 설치 없이 바로 켜지는 작은 복제 서버를 준다. 그리고 채점 스크립트 대신 "채울 수 없는 칸은 비워 두는가"까지 보는 정답 예시를 준다.

## 배경과 제약

회사 조직과 분리한 일회용 GitHub 조직에 비공개 레포 하나를 만들었다. 처음에는 회사 조직에 빈 레포를 만들었다가, 분리하기로 정하고 지웠다. 무료 조직이라 브랜치 보호를 걸 수 없어서, 학생 이메일 앞부분으로 브랜치 5개를 미리 만들고 "자기 브랜치에서만 작업"을 README 규칙으로 적었다.

## 선택

| 갈림길 | 고른 것 | 덧붙임 |
|---|---|---|
| 회사 서버를 포크할까 | 포크하지 않고 필요한 것만 새로 작성 | API 주소·응답 형식은 실제 서버와 같게, 로그인은 없음 |
| 실행 환경 | 도커 없음. 내장 H2 파일 DB, 서버가 빌드 없는 HTML+JS 를 그대로 서빙 | 설치할 것이 JDK 하나뿐이고 Node가 필요 없다. 화면 파일을 고치고 새로고침만 하면 반영된다 |
| 학생이 어디에 손대나 | 화면에 버튼 두 개와 빈 함수만 두고, "폼 채우기"·"체급 제안 표시" 함수는 미리 제공 | AI가 채운 칸은 보라색으로 표시하고 사람이 고치면 표시가 사라지며, 체급 제안은 사람이 「한 번에 선택」을 눌러야 반영된다 |
| 채점 | 스크립트 없음. 공고 3개에 대한 정답 예시만 | 평가 기준을 셋으로 적었다. 같은 공고를 여러 번 넣어도 같은 결과인가, 사람이 고치지 않고 쓸 수 있는 값이 몇 개인가, 공고에 없는 값을 억지로 채우지 않는가 |
| 샘플 공고 | 실제 공고 hwp 20개를 골라 넣고 내용은 고치지 않음. 파일명은 앞 번호만 붙임 | 종목을 구별하는 것도 과제라서 파일명에 종목을 붙이지 않았다 |

대회 생성 폼에는 공고에 절대 나오지 않는 운영 설정 칸(공개 일시, 숨기기 등)이 있다. 이 칸을 일부러 남겨 뒀다. AI가 이 칸을 채우면 지어낸 것이니 검증용으로 쓸 수 있다.

## 막혔던 것

- **체급 목록이 운영과 달랐다.** 시작 데이터로 개발 DB 스냅샷을 썼더니, 개발 DB에서는 사용 중지된 부문을 운영의 샘플 대회들은 쓰고 있었다. 샘플 20개 대회가 운영에서 실제로 쓴 부문·체급 65행을 사용 중으로 바꿨고, 유도 화면에 보이는 행이 466개에서 1,273개로 늘었다. 운영에서 대회마다 새로 만든 체급 26개는 개발 DB에 아예 없어서, 학생 과제의 「새로 추가」 대상으로 남겼다.
- **정답 예시를 만들다 보니 "정답"이 둘이었다.** 공고 원문과 운영자가 실제로 입력한 값이 다른 곳이 있었다(부문 이름 표기, 공고에 없는 부문 등). 정답은 공고 원문 기준으로 하고, 운영 입력과 다른 곳은 별도 항목으로 적었다. 한 공고는 hwp 미리보기 텍스트의 날짜가 본문과 달랐다. 미리보기만 읽는 추출기는 틀린 날짜를 낸다.
- **대회 생성 요청이 서버에서 거절됐다.** 폼 항목이 많은 multipart 요청이 내장 Tomcat의 기본 파트 수 한도를 넘었다. `max-part-count` 를 200으로 올렸다.

## 결과와 대가

- 하루 동안 커밋 4개를 올렸다(공고와 README → 서버·화면·체급 목록·예시 → 결과 예시로 대회 3개 미리 생성 → 체급 조회 화면). README는 사람이 그대로 따라 하는 설명서로 쓰되, 학생이 Claude Code에 "README대로 해 줘"라고 해도 진행되게 단계마다 확인 방법을 붙였다.
- 같은 날 학생 한 명이 자기 브랜치에 hwp 추출 연동과 클라우드 배포(다른 DB, 화면 투어)까지 올렸다. 그 브랜치는 건드리지 않는다. 다만 main을 합치면 시작 데이터 실행기가 충돌하고, 시작 SQL의 `INSERT IGNORE` 가 그쪽 DB(PostgreSQL)에서 그대로 돌지 않는다.
- 대가: 체급 목록은 스냅샷이라 운영에서 체급이 바뀌어도 따라가지 않는다.

## 남은 것

- 이 과제는 10-20 강의에서 본 RAG의 "추출" 단계를 실제 문서로 해 보는 일이다. 평가 기준 세 개(같은 입력 같은 결과, 그대로 쓸 수 있는 값, 없는 값은 비움)는 골든셋의 세 가지 질문(답 있음, 표현 바꿈, 답 없음)과 같은 구조다.
