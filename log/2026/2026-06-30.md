# 2026-06-30

**요약**: 사용자/관리자/점수판마다 따로 있던 Repository를 엔티티당 하나로 합치고(13 PR), 어노테이션 문자열 쿼리를 QueryDSL로 옮기고, 레이어 우선 패키지를 도메인 우선으로 뒤집기 시작했다. 중간에 헥사고날 표준을 한 번 세웠다가 폐기했고, CQRS는 전수 조사 끝에 보류했다.

## 배경과 제약
같은 엔티티를 사용자·관리자·점수판 도메인마다 별도 Repository로 중복 정의하고 있었다. 한 도메인의 컨트롤러·서비스·DTO·엔티티가 레이어별 폴더에 흩어져 변경 하나가 여러 폴더를 만졌다. 합격선은 행동 보존. URL과 외부 동작은 바꾸지 않는다.

## 선택
순서를 못 박았다. ① Repository 통합(엔티티로 모으기) → ② `@Query` → QueryDSL → ③ 쿼리 분리. ①②는 끝냈고 ③은 아래 이유로 보류.

- **Repository 통합**: 엔티티 1개 = Repository 1개, `entity/{도메인}/repository`. 소비처가 많은 엔티티(26곳, 39곳)는 PR을 따로 뗐다.
- **QueryDSL 전환**: 분류를 두 갈래로만. 순수 where → 파생 쿼리 메서드, fetch·다중 조인·projection·MAX·동적 → QueryDSL. 엔티티당 PR 1개, PR 안은 [커밋1 characterization 테스트(구 코드 green) → 커밋2 전환(같은 테스트 green = 등가 증명)]. fetch join은 "연관이 로드됐는가" 단언을 꼭 넣어 N+1 회귀를 막는다.
- **package-by-domain**: 컨트롤러+서비스+DTO 수직 슬라이스를 통째로 도메인 패키지로. 공유 모듈은 오너가 있으면 오너 도메인에, 없으면 코어에. 코어→액터 역방향은 포트로 끊는다.

## 막혔던 것 — 뒤집힌 것 두 개
**헥사고날 표준 폐기.** 한때 헥사고날/BFF/공유 커널 구조를 문서로 세우고 "컨트롤러는 액터별 BFF라 통합하지 않는다"고 결론냈었다. 도메인 통합을 진행하면서 그 결론이 뒤집혔다. Repository가 도메인으로 모였듯 컨트롤러도 도메인으로 모으는 게 맞았다. 문서는 삭제했다.

**CQRS 보류.** ③에서 Read/Command Repository를 가르려고 쓰기 메서드를 셌는데, 처음 기억은 "5개"였다. `@Modifying`만 센 숫자였다. 파생 `deleteBy…`, QueryDSL DML `.execute()`, `@Lock`까지 네 군데 신호를 다 보니 **11개 Repository, 59개**였다. 그리고 `save()`가 JpaRepository 기본이라 "타입으로 쓰기를 차단"하는 실익을 얻으려면 59개를 전부 손대야 했다. ROI 음수. 완전 CQRS도 실용 CQRS도 접고, `@Modifying @Query` 7개를 QueryDSL로 옮기는 것만 남겼다. 단일 신호로 세지 말 것.

작업 중 사고도 있었다. 다른 워크트리에서 브랜치를 바꾸는 사이 내 커밋이 엉뚱한 브랜치에 올라갔고, 리베이스 중 다른 기능 커밋이 내 PR에 섞여 들어갔다. `format-patch`로 백업 → 브랜치 포인터 되돌리기 → 재적용 → `--force-with-lease`로 복구. 그 뒤로 커밋 직후 `branch --contains`로 위치를 확인하고, behind 카운트는 양쪽 다 본다(ahead만 보면 stale을 최신으로 오독한다).

## 결과와 대가
- Repository 통합 13 PR 전부 머지. `@Query` 33개 중 전환 15, 파생 3, 유지 14(native 2개 포함). 호출처 0인 쿼리 1개는 전환 대신 삭제.
- 발견 하나: Hibernate 6는 컬렉션 LEFT JOIN FETCH 시 root를 자동 dedupe한다. 구버전 기억으로 size 3을 기대한 테스트가 2로 실패해서 알았다. test-first가 아니었으면 "전환하면서 결과가 바뀐 것"으로 오해했을 것이다.
- 대가: 서비스 이동이 쓰기 감사 로그 AOP 포인트컷을 조용히 빠뜨릴 수 있다. 동료가 포인트컷을 구·신 경로 와일드카드로 두고 표현식↔클래스 위치를 리플렉션 테스트로 고정해 막았다.
