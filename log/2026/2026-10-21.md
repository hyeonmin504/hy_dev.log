# 2026-10-21

**요약**: 에러 알림에 Claude 원인 분석 답글을 다는 데(10-14) 이어, 이슈 트래커에 붙는 Claude 코딩 에이전트로 수정 PR까지 만들지 정했다. 분석은 모든 에러에 자동으로 달고, PR은 사람이 이슈를 에이전트에 할당한 것만 만든다. 할당하는 행동 자체가 승인이다. 준비 상태를 점검하다가, 10-14에 만든 분석 흐름이 운영 환경에서는 한 번도 돌지 않았다는 걸 발견했다.

## 배경과 제약

이슈 트래커에 설치하는 Claude 코딩 에이전트 앱이 나왔다. 이슈를 할당하거나 멘션하면 에이전트가 레포를 읽고 draft PR을 만든다. 우리 API 키로 돌아가서 팀 플랜의 월 API 크레딧으로 비용을 낼 수 있다. 이슈에는 요약·설명·대상 레포 필드가 있어야 한다.

## 선택

| 안 | 내용 | 결과 |
|---|---|---|
| A | 새 에러가 나면 이슈를 자동으로 만들고 에이전트에 자동 할당해 PR까지 | 버림 |
| B | 분석 답글은 모든 에러에 자동. PR은 사람이 고른 이슈만(할당 = 승인) | **선택** |

A를 버린 이유는 코드 결함이 아닌 데이터 상태 에러까지 PR이 쌓이고 크레딧이 새기 때문이다. PR은 필요한 것만 만든다. 분석 답글은 지금처럼 전부 자동으로 두고, 쓰기(PR)만 사람의 판단 한 번을 거치게 했다. 자동 할당 규칙은 만들지 않는다.

시범 대상으로는 운영에서 실제로 났던 에러 하나를 골랐다. 관리 화면에서 같은 수정 요청이 연달아 두 번 들어와 JPA 의 `StaleStateException` 이 난 건으로, 같은 파일 제거 경로가 네 곳에 공통으로 있다.

## 막혔던 것

- 앱이 아직 설치돼 있지 않았다. 이슈 트래커 사용자 검색에 에이전트가 안 나왔고, 버그 이슈 유형에는 대상 레포 필드가 없었다. 설치와 필드 추가에는 관리자 권한이 필요하다.
- 준비물을 확인하다가 **운영 환경에서는 에러 분석 워크플로 실행 기록이 0건**인 걸 봤다. 기록은 전부 staging이었고 마지막이 10-15였다. 10-14에는 staging에서 에러 발생 50초 뒤 답글이 달리는 것까지만 확인했고, 운영에서는 확인하지 않았다. 원인 후보는 두 가지다. 운영 서버에 워크플로를 호출할 토큰이 설정되지 않았거나, 호출(dispatch)이 실패하고 있거나. 아직 어느 쪽인지 모른다.

## 남은 것

- 에이전트 앱 설치, 버그 유형에 레포 필드 추가, 크레딧 연결 확인
- 운영에서 분석 워크플로가 돌지 않는 원인 확인. 에이전트를 붙이기 전에 그 앞 단계부터 운영에서 동작해야 한다.
