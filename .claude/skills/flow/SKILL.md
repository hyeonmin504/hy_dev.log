# /flow — 코드 → 흐름 슈도코드

## 입력

`$ARGUMENTS` 는 셋 중 하나. 레포가 불분명하면 `~/sportsprism/*` 를 grep 해서 찾고, 둘 이상이면 묻는다.
- 파일 경로 또는 심볼명 (`AdminMatchStatusService.updateStatus`)
- 자연어 설명 ("경기 상태 확정 후 다음 라운드 전파")
- 이미 열어둔 대화 맥락 ("방금 본 그 메서드")

## 절차

1. **읽기 전용.** 형제 레포 파일은 Read/Grep 만. Edit·Write 금지.
2. 진입점을 잡고 아래 순서로 추출한다. 호출 깊이는 기본 2단계. 더 깊은 건 `…` 로 접고 필요하면 묻는다.
   - 입력 (파라미터, 선행 조건)
   - 분기 (if/switch, 조기 반환, 예외)
   - 외부 호출 (DB 조회·저장, 네트워크, 브로드캐스트, 캐시, 트랜잭션 경계)
   - 출력과 부수효과
3. 식별자를 **역할명**으로 바꾼다. 클래스·메서드·필드·패키지 실명을 남기지 않는다.
4. CLAUDE.md 형식의 `pseudo` 블록으로 쓴다. 10~20줄. "왜 이 순서인가" 주석 1~2개는 코드 주석·커밋 메시지·테스트 이름에서 근거를 찾아 단다. 근거 없으면 `[확인]` 표시.
5. 컴포넌트 3개 이상이면 mermaid `sequenceDiagram` 을 옵션으로 덧붙인다. 참여자도 역할명.
6. **일반화표**를 블록 아래 같이 낸다. 사용자가 새는 게 없는지 눈으로 확인하는 용도.

   | 원본 | 표기 |
   |---|---|
   | `XxxService.doThing` | 상태 서비스.확정 |

7. 출력은 블록 + 표 + `출처: <레포명> <영역>` 한 줄. **파일에 넣지 않는다.** 넣는 건 `/log` 또는 `/promote` 가 한다.

## 하지 않는 것

- 코드 라인을 옮겨 적고 변수명만 바꾼 것. 그건 흐름이 아니라 번역이다. 한 줄이 코드 한 줄에 대응하면 다시 쓴다.
- 모든 분기를 다 적는 것. 일지의 맥락(막혔던 지점·버그 지점)에 관련된 분기만 남기고 나머지는 한 줄로 접는다.
- 테스트 코드 복사. 테스트는 "어떤 케이스를 보장하는가" 한 줄로.
