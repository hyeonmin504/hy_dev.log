# /log — 오늘 일지

## 절차

1. `date +%Y-%m-%d` 로 오늘 날짜. 파일은 `log/YYYY/YYYY-MM-DD.md`. 연도 폴더 없으면 만든다.
2. 재료 모으기
   - 사용자가 준 인자(`$ARGUMENTS`)가 1차 재료.
   - 보조 재료: 형제 레포의 오늘 내 커밋. 커밋 메시지는 **기억을 되살리는 용도**일 뿐, 그대로 옮기지 않는다.
     ```
     for r in ~/sportsprism/*/; do [ -d "$r/.git" ] && git -C "$r" log --author="$(git config user.email)" --since=midnight --format='%s' 2>/dev/null; done
     ```
   - 인자가 없고 커밋도 없으면 "오늘 뭐가 있었나" 한 번만 묻고 멈춘다.
   - (예정) 지라 이슈·브랜치 같은 외부 소스는 아직 연결하지 않는다. 사용자가 추가하면 여기에 절차를 넣는다.
3. 재료의 성격을 가른다. 사용자는 보통 **방향과 정보**를 주고, 문장은 일부만 준다.
   - 사용자가 준 **문장은 그대로 쓴다.** 어순·단어를 바꾸지 않는다. 내가 하는 건 문장 사이를 잇고 순서를 잡는 것뿐이다.
   - 방향·정보만 있는 부분은 내가 서사로 엮되, **지어내지 않는다.** 가설·측정값·"왜 그렇게 생각했는지"가 비어 있으면 묻는다.
   - 질문은 **한 번에 묶어서** 던진다. 꼭 필요한 것만, 하나씩 번호로. 답이 안 온 빈칸은 `[확인]`으로 남기고 메우지 않는다.
4. `templates/log.md` 형식으로 초안 작성. 첫 줄 `**요약**:` 1~2문장 필수. 본문 5~12줄, 시간순, 틀렸던 가설 포함, 측정값은 숫자. 마지막 줄 `태그:`.
   - **원문이 길 때**(30줄 이상, 또는 보고서·회의록 형식): 먼저 배경·제약·선택·흐름·막힘·결과·남은 것으로 분류하고, 각 항목을 압축한다. 목표 분량은 원문의 1/4 이하. 소제목은 템플릿의 것만 쓰고 빈 소제목은 뺀다. 코드·절차가 있으면 CLAUDE.md "표현 방식 고르기"대로 형식을 하나 골라 블록 하나로 — 한 행위자의 순서는 `pseudo`, 둘 이상이 시간순으로 엇갈리면(경합·전파·재연결) `sequenceDiagram`, 구조 비교는 `flowchart`. 같은 내용을 두 형식으로 반복하지 않는다.
   - 원문에 날짜가 있으면 그 날짜 파일에 쓴다. 오늘이 아니어도 된다.
   - 한 원문에 주제가 둘 이상이면 파일을 나눌지 묻는다.
5. 내부 정보 일반화 (CLAUDE.md 공개 규칙). 티켓 번호·도메인 용어·실명 제거. 애매하면 `[확인]` 표시.
6. 파일이 이미 있으면 **덧붙인다**(기존 문단 수정 금지). 구분은 빈 줄 하나.
7. **첫 문단 삭제 테스트.** 요약 줄 다음 첫 문단을 지워도 글이 읽히면 지운다. 읽힐 때까지 반복한다. 배경 설명·역사·"~하게 됐다"로 시작하는 문단이 주로 걸린다.
8. 초안을 보여주고 끝. 커밋하지 않는다. `/index` 실행은 사용자가 원할 때.

## 하지 않는 것

- 체크리스트("한 일 / 배운 것") 형식으로 쓰지 않는다.
- 커밋 메시지를 문장으로 풀어 쓴 것만 나열하지 않는다. 커밋에 없는 "왜"와 "막힘"이 본문이다.
- 하루에 여러 일이 있으면 가장 생각이 많았던 하나를 길게, 나머지는 한 줄.
